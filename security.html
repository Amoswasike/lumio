SECURITY & DATA PRACTICES

Built with clarity and data ownership in mind.

Lumio's security and privacy information is designed to describe what the application actually does today, without making unsupported infrastructure claims.

Account access

Lumio separates the public website from the authenticated application experience. Account access and authenticated financial activity belong to the application layer.

User-owned financial records

Authenticated financial records are associated with the relevant user account. The application is designed around keeping one user's financial information separate from another user's information.

Controlled application structure

Lumio separates responsibilities between views, controllers, services, models, storage, and application state. This structure helps keep financial operations organized and predictable.

Validation and state management

The application uses validation, controlled state management, and event-driven updates as part of its current architecture.

CURRENT V1 ARCHITECTURE

How financial data is handled today.

The current Lumio V1 application uses a browser-based, client-side data architecture. Financial records are currently stored on the user's device through browser storage rather than through a production cloud database.

This means the current implementation should not be described as providing the same security infrastructure as a bank or financial institution.

Users should protect their account credentials and the devices they use to access Lumio.

TRANSPARENT PRODUCT CLAIMS

Security claims should match implemented capabilities.

Lumio intentionally avoids describing capabilities that have not been implemented and verified.

No bank connection claim

Lumio does not currently provide direct bank synchronization. The public website does not imply bank connectivity until such a capability is implemented.

No unsupported encryption claim

Lumio does not describe the current application using unsupported claims such as “military-grade encryption” or “bank-grade security.”

No unsupported cloud infrastructure claim

The current V1 architecture should not be described as using cloud synchronization, production databases, managed backups, or third-party financial infrastructure unless those capabilities are actually implemented and verified.

FUTURE ARCHITECTURE

Security documentation will evolve with Lumio.

As Lumio moves from its current client-side architecture toward a production backend, the security documentation should be updated to describe the actual implementation.

This may include authentication mechanisms, database access controls, encryption, backups, logging, hosting infrastructure, session management, and account and data-deletion processes once those capabilities exist and have been verified.

PRODUCT SCOPE

Lumio is a personal finance management application.

Lumio helps you understand, organize, and manage your everyday finances in one place.

It is not a bank, investment platform, or financial institution.
